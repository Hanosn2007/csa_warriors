Java Warrior Arena

一个用 Java 编写的回合制策略竞技项目。你会在网格地图上控制自动战斗战士，通过代码决定它每一步移动、攻击、防御、抢道具或撤退。

项目已经准备好地图、回合系统、图形界面、批量测试和评分统计。你主要修改：

src/TeamAlphaWarrior.java

多个队伍策略放进同一个项目做 PK 时，每个队伍使用自己选择的唯一策略名。名称只能包含英文字母、数字和下划线，第一个字符必须是英文字母，文件名、public class 名和构造方法名三处一致。格式示例：AuroraBlade.java / public class AuroraBlade extends Warrior / public AuroraBlade()。

环境要求

  • JDK 17 或更高版本
  • 不需要下载游戏引擎
  • 不需要 Maven 或 Gradle

双击启动

Windows 中可以直接双击项目根目录的：

启动仿真UI.bat

它会自动编译全部 Java 文件，并打开可视化仿真界面。编译失败时会保留错误信息窗口。

macOS 中可以直接双击项目根目录的：

启动仿真UI.command

如果 macOS 提示没有权限，打开“终端”，进入项目文件夹后执行一次：

chmod +x 启动仿真UI.command

之后再双击 启动仿真UI.command 即可。

VS Code 运行方式

用 VS Code 打开整个项目文件夹 csa_warriors，不要只打开单个 .java 文件。

第一次使用时：

  1. 安装 JDK 17 或更高版本。
  2. 安装 VS Code 的 Extension Pack for Java。
  3. 打开项目文件夹后，等待 VS Code 识别 Java 项目。

运行方式：

  • 按 Ctrl+Shift+B：编译全部 Java 文件。
  • 打开“运行和调试”，选择 Visual Debugger：启动可视化调试界面。
  • 打开“运行和调试”，选择 Console Match：启动控制台比赛。
  • 也可以打开命令面板，运行 Tasks: Run Task，选择 run visual debugger 或 run console match。

如果 VS Code 提示找不到 javac 或 java，说明 JDK 没有正确安装，或 JDK 的 bin 目录没有加入系统环境变量 PATH。

终端运行

图形界面：

javac --release 17 -encoding UTF-8 -d out src\*.java
java -cp out ArenaUiMain

控制台比赛：

javac --release 17 -encoding UTF-8 -d out src\*.java

可视化调试界面

项目提供 Swing 图形界面，不需要额外下载 UI 引擎。

  • 彩色网格地图
  • 墙、治疗点、队伍位置显示
  • 战士生命条
  • 最近一次行动的战士高亮

游戏规则

  • 地图是二维网格。
  • 格子类型有普通地面、墙、治疗点。
  • 支持 4 个队伍，每队 2 到 3 个战士。
  • 每个回合中，队伍按顺序行动，每个存活战士行动一次。
  • 比赛没有固定总回合上限。
  • 如果连续 30 个完整回合没有任何状态变化，比赛触发无进展判负并结束。
  • 状态变化包括单位位置、生命、存活状态、防御状态、攻击/范围数值、地图道具位置或类型变化。
  • 行动支持 MOVE、ATTACK、DEFEND、STAY。
  • 治疗点会自动恢复 8 点生命值。
  • 地图上会随机刷新辅助道具。
  • H / Health Pack：恢复生命值。
  • A / Attack Gem：增加攻击力。
  • L / Range Lens：增加攻击范围。
  • M / Mega Health：大量恢复生命值。
  • P / Power Core：大幅增加攻击力。
  • C / Battle Core：恢复生命，同时增加攻击力和攻击范围。
  • 默认开局生成 5 个道具，后续低频随机刷新，最多同时存在 5 个道具。
  • 新道具会尽量刷新在距离所有存活战士至少 3 格的位置；强力道具至少 4 格。
  • 强力道具总概率较低，主要作为阶段性争夺目标。
  • 攻击目标在范围内时造成固定伤害。
  • 如果目标正在防御，本次伤害减半。
  • 当生命值小于等于 0 时，战士被击败。
  • 如果策略代码返回 null 或抛出异常，本回合自动 STAY。

调试流程

  1. 先运行 ArenaUiMain。
  2. 点击“下一步”，观察一个战士本回合做了什么。
  3. 先看“策略意图”，再看地图动画和战斗日志。
  4. 点击某个战士，查看它的生命、攻击力、范围、加成和位置。
  5. 判断 chooseAction 是否符合预期。
  6. 修改自己的策略后，重新编译并运行 UI。

最小策略代码

public class TeamAlphaWarrior extends Warrior {
    public TeamAlphaWarrior() {
        super("Team Alpha");
    }

    @Override
    public Action chooseAction(GameState state, UnitInfo self) {
        UnitInfo enemy = state.findNearestEnemy(self);

        if (enemy == null) {
            return Action.stay();
        }

        if (self.distanceTo(enemy) <= self.getRange()) {
            return Action.attack(enemy.getId());
        }

        return state.moveToward(self, enemy.getPosition());
    }
}

评分系统

项目包含综合评分系统，不只看最后谁获胜。

评分会统计：

  • 造成伤害
  • 击败敌人
  • 拾取道具
  • 有效回血
  • 存活回合
  • 最终存活
  • 胜利奖励
  • 无效行动扣分
  • 连续无进展扣分

总评分按 100% 计算：

评分项目占比
代码能运行15%
Java 基础使用20%
策略设计25%
测试与修改记录15%
比赛综合评分15%
代码讲解10%

独立完成是提交前提。不要使用生成式工具、代码代写工具或他人生成的完整策略代码。

评分参数集中在 ScoreConfig.java，参数说明见 评分参数表。
